# Voxel-SLAM 重定位、连续定位与高频里程计文档设计

## 目标

在根目录 `README.md` 中补充当前定位实现的完整数据流，使读者不阅读源码也能回答以下问题：

- BTC 自动重定位与 RViz 人工初始化分别如何工作；
- 两条通道如何得到并应用当前局部里程计坐标系到历史地图坐标系的变换；
- 为什么 RViz 位姿不能直接视为有效定位；
- 空间块局部地图如何准备并进入 `IN_MAP_TRACKING`；
- 连续定位如何维护地图、执行点到面 IESKF 并处理失效；
- 正式扫描批处理 IESKF 与 IMU 高频预测链路如何并行工作和输出导航接口。

## 文档组织

根 README 是完整说明的唯一来源，避免与 `VoxelSLAM/README.md` 重复维护长篇内容。现有定位章节按运行顺序扩充：

1. 在 BTC 配置说明后增加双通道总览和状态流。
2. BTC 通道说明候选筛选、BTC 描述子匹配、平面 ICP 验证、GTSAM LM 会话对齐及全局校正。
3. RViz 通道说明 x/y/yaw、IMU roll/pitch、最近历史关键帧高度和连续多帧局部地图验证。
4. 公共路径说明 `PREPARING_LOCAL_MAP`、空间块异步加载、不可变局部地图快照、点到面 IESKF、质量判定及 `LOST` 恢复。
5. 扩充高频里程计章节，分别描述正式 IMU 缓冲路径和独立 IMU callback queue 快速路径，并说明时间戳、TF 所有权、有效定位门控、预测时限和车辆里程计适配。

## 准确性边界

- 不再把当前重定位描述为 BnB、GN 或 SE-Sync。
- BTC 不是最终位姿的唯一验证：匹配后仍执行平面 ICP 和 GTSAM Levenberg–Marquardt 会话对齐。
- RViz 是人工初始化通道，不是自动重定位算法；只有连续局部历史地图匹配通过后才设置 `/localization/valid=true`。
- BTC 路径在跨 Session 约束验证、全局校正和核心空间块就绪后进入有效定位；RViz 路径还需要连续扫描验证。
- 高频 IMU 预测不写回正式滤波器，也不替代扫描批处理 IESKF 的去畸变、协方差传播和点到面后验更新。

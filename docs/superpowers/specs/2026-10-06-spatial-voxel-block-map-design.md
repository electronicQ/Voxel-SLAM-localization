# Voxel-SLAM 三维空间体素块地图设计

**日期：** 2026-10-06
**状态：** 已讨论确认，等待实施计划与代码实现
**实施分支：** `codex/spatial-voxel-blocks`
**基线标签：** `localization-v1-baseline`

## 1. 改造目标

当前定位版本以历史关键帧为局部地图加载和卸载单位。活动关键帧集合一旦变化，就需要重新合并所有活动关键帧点云、重新体素化并重建 `surf_map` 中的八叉树和平面。这会在里程计线程中产生明显计算尖峰。

本次改造将连续定位参考地图替换为离线预构建、运行时只读的三维空间体素块，使地图能够按空间增量加载和卸载，并满足以下目标：

1. 连续定位不再因为关键帧集合变化而完整重建局部体素地图；
2. 加载新块或卸载旧块不会改变其他活动块；
3. IESKF 点到面匹配期间不加锁、不切换地图；
4. 建图往返经过同一区域产生的重复观测在导出阶段融合；
5. 保留现有 BTC、ICP、GTSAM、RViz 初始化、定位质量监控和 `LOST` 恢复流程；
6. 保留历史关键帧地图，使其继续服务于 BTC、几何验证、最近高度查询和空间块离线重建。

本次改造不改变建图模式的实时滑窗体素地图，也不把定位时的新扫描写入固定历史地图。

## 2. 总体架构

地图包 v2 同时保存两类地图：

```text
地图包 v2
├─ 关键帧与 BTC 层
│  ├─ 最终优化关键帧位姿和局部点云
│  ├─ BTC 描述子
│  └─ BTC 几何验证平面云
│
└─ 连续定位空间块层
   ├─ 三维规则块索引
   ├─ 预构建只读八叉树
   ├─ 预计算平面及不确定性
   └─ 可选显示点云
```

关键帧与 BTC 层负责全局重定位。空间块层只负责重定位成功后的连续 LiDAR—历史地图点到面匹配。两个层次用途不同，不相互替代。

## 3. 三维空间划分

### 3.1 默认尺寸

空间块采用与 `map` 坐标系对齐的三维规则网格，默认尺寸为：

```yaml
MapBlock:
  size_x: 20.0
  size_y: 20.0
  size_z: 10.0
  fusion_leaf_size: 0.1
  root_voxel_size: 1.0
```

块索引概念上为：

```text
bx = floor(x / size_x)
by = floor(y / size_y)
bz = floor(z / size_z)
```

实际代码必须通过一套共享索引函数完成世界坐标、顶层体素索引和块索引转换，不能在导出器和定位器中分别实现。该函数需要对负坐标和恰好位于边界的坐标进行单元测试。

### 3.2 对齐约束

- 三个块尺寸都必须是 `root_voxel_size` 的整数倍；
- 一个顶层体素只能属于一个空间块；
- 先确定顶层体素整数索引，再通过整数除法确定所属块，避免浮点边界产生歧义；
- 不在相邻块之间复制点、体素、八叉树节点或平面；
- 块尺寸、融合分辨率、顶层体素尺寸和八叉树参数是地图格式的一部分，定位运行时不得覆盖。

现有点到面 `match()` 只查询世界点所在的顶层体素，然后沿对应八叉树分支向下查找，因此上述无重叠划分不会改变其邻域语义。

## 4. 离线地图构建

### 4.1 构建时机

建图直接导出 v2 时，空间块必须在最终回环优化、PGO 和必要的 GBA 完成后生成。所有输入位姿必须是最终优化位姿。

同时提供 v1 到 v2 的离线转换工具。转换工具读取 v1 地图中的最终关键帧和点云，不要求重新播放建图数据。

定位进程不在启动时临时构建空间块。加载 v1 地图时应明确拒绝，并提示用户先运行离线转换工具。

### 4.2 跨关键帧融合

空间块构建流程为：

```text
最终关键帧局部点云
  → 使用最终位姿变换到 map 坐标系
  → 按 0.1 m 细粒度融合体素聚合跨帧重复观测
  → 为每个融合体素生成代表点和统计量
  → 按 1.0 m 顶层体素组织数据
  → 自适应构建静态八叉树
  → 计算叶节点平面和不确定性
  → 按顶层体素所属块写入空间块
```

细粒度融合体素至少累计点数、位置和二阶统计量，并生成质心、平均强度和测量不确定性。这样多次经过同一区域不会按关键帧重复保存相同位置的点，也不会保留关键帧归属关系。

构建器必须按关键帧 ID、块索引、顶层体素索引和节点顺序进行确定性排序。相同输入和相同参数应生成内容一致的空间块。

### 4.3 静态八叉树

空间块不直接序列化现有 `OctoTree*`。新增无裸指针的静态数据结构：

```text
StaticMapBlock
├─ RootVoxelRecord[]
├─ StaticOctreeNode[]
├─ StaticPlane[]
└─ DisplayPoint[]（可选）
```

- 根体素记录保存块内顶层体素索引和根节点数组下标；
- 八叉树节点通过数组下标连接八个子节点，无子节点使用无效下标；
- 叶节点保存平面数组下标；
- 平面保存匹配需要的中心、法向、半径、平面协方差及质量字段；
- 运行时对象全部只读，不能插入当前扫描或修改平面统计量。

静态匹配器的数学门限和原版 `OctoTree::match()` 保持一致。实施时需要用同一批点和查询点对两种实现做等价性测试。

## 5. 磁盘格式

地图包 v2 新增：

```text
map_package/
├─ manifest.yaml
├─ keyframes.csv
├─ keyframes/
├─ btc_frames.bin
├─ btc_planes/
├─ spatial_blocks.idx
└─ spatial_blocks.bin
```

### 5.1 索引文件

`spatial_blocks.idx` 保存格式头和所有非空块的轻量元数据：

- 块三维整数索引；
- 世界坐标 AABB；
- 在 `spatial_blocks.bin` 中的偏移和长度；
- 根体素数、八叉树节点数、平面数和显示点数；
- 单块校验码。

索引加载后建立 `unordered_map<BlockIndex, BlockIndexEntry>`。运行时根据加载球覆盖的块索引整数范围做少量枚举和 AABB—球相交测试，再在哈希索引中查询非空块，不遍历全部历史块。

### 5.2 数据文件

`spatial_blocks.bin` 按确定性顺序连续保存每个块。后台加载线程通过索引中的偏移和长度随机读取目标块。

二进制格式要求：

- 字段逐项读写，不直接写入 C++ 结构体内存；
- 不保存裸指针、容器内部布局或编译器填充字节；
- 格式头记录魔数、版本、字节序和标量类型；
- 所有计数、偏移和乘法在分配内存前检查溢出；
- 对非有限浮点数、非法子节点下标、重复根体素和越界平面下标拒绝加载；
- 每块独立校验，错误信息包含块索引；
- 初版不压缩，避免运行时解压缩造成 CPU 峰值。

### 5.3 地图清单与原子发布

`manifest.yaml` 升级为 v2，记录空间块尺寸、融合分辨率、顶层体素尺寸、八叉树参数、平面门限、块数量、文件大小和参数指纹。

地图导出继续先写临时目录。所有文件关闭并完成一致性检查后，再原子发布最终目录，避免中断写入产生表面完整但实际缺失的数据包。

## 6. 运行时两级只读索引

每个世界点的查询路径为：

```text
世界点
  → 共享索引函数计算 BlockIndex
  → 在当前 ActiveSpatialMap 中查找 StaticMapBlock
  → 计算块内 RootVoxelIndex
  → 查找根节点并沿静态八叉树下降
  → 返回只读 StaticPlane
```

活动地图不再合并成新的全局 `surf_map`，也不复制活动块中的八叉树节点。加载一个块只增加一个独立块对象；卸载一个块只从下一份活动集合中去掉该块。

定位模式的 IESKF 使用静态匹配器。建图模式继续使用原版动态 `surf_map` 和 `OctoTree`，二者保持隔离。

## 7. 每 Scan 固定地图快照

后台线程负责读取、校验和反序列化空间块。里程计线程在每个 Scan 开始时取得一次 `shared_ptr<const ActiveSpatialMap>`，并在整次 IESKF 迭代期间持有该快照。

因此：

- 同一 Scan 的多次 IESKF 迭代看到完全相同的活动地图；
- 点级查询不需要互斥锁；
- 缓存在迭代间复用的静态八叉树节点指针在该 Scan 内始终有效；
- 后台线程发布新快照不会使当前 Scan 的块失效；
- 旧块在最后一个快照引用释放后自动销毁。

活动块集合较小，发布新版本时只复制块 ID 到共享块对象的轻量映射，不复制块内节点和平面数组。

地图管理器带有 Session 代数。重新定位、`LOST` 清理或地图重载后，旧代数的异步加载结果必须丢弃，不能重新发布到新 Session。

## 8. 加载、预取与卸载

建议运行时参数为：

```yaml
Localization:
  spatial_map:
    preload_radius: 15.0
    load_radius: 30.0
    unload_radius: 40.0
    prefetch_time_sec: 2.0
    map_gap_timeout_sec: 1.0
    preload_timeout_sec: 10.0
    max_background_loads: 2
```

参数约束：

```text
0 < preload_radius <= load_radius <= unload_radius
```

运行规则：

1. 候选全局位姿确定后，优先加载 `15 m` 核心范围内存在的非空块；
2. 核心块完成后才允许使用该位姿进入后续有效性流程；
3. `30 m` 范围内其他块由后台继续补齐；
4. 预取中心使用当前预测位置与 `velocity × prefetch_time_sec` 的前视位置，并始终保留当前核心范围；
5. 加载队列按车辆到块 AABB 的距离排序，核心块优先；
6. 块 AABB 完全离开 `40 m` 范围后，才从下一份快照卸载；
7. 卸载只移除共享块引用，不重建其他块。

## 9. 定位状态机

增加显式状态：

```text
PREPARING_LOCAL_MAP
```

BTC 路径：

```text
LOCAL_ODOMETRY
  → RELOCALIZING
  → ALIGNING
  → PREPARING_LOCAL_MAP
  → IN_MAP_TRACKING
```

RViz 路径：

```text
LOCAL_ODOMETRY
  → ALIGNING
  → PREPARING_LOCAL_MAP
  → 使用局部历史地图验证连续若干 Scan
  → IN_MAP_TRACKING
```

`PREPARING_LOCAL_MAP` 期间：

- `localization_valid=false`；
- 不累计匹配坏帧；
- 发布正在加载的块数、待加载块数和核心覆盖率；
- 预加载超时、附近无可用地图或必需块损坏时，初始化失败；
- RViz 的匹配验证超时从核心地图就绪后开始计时，不包含磁盘预加载时间。

BTC 已经通过描述子、几何验证、ICP 和 GTSAM 对齐，因此核心地图就绪后可进入连续定位；RViz 位姿仍必须通过配置数量的连续 Scan 点到面质量验证。

## 10. 加载延迟保护

后台加载未完成时，不应把地图不完整直接当作定位算法失败。

每个 Scan 先使用当前活动快照正常匹配：

- 如果匹配质量合格，即使外围预取块尚未全部加载，也正常执行点到面更新；
- 如果匹配不足且必要块仍在加载，则本帧只保留 IMU 传播结果，不累计 `LOST` 坏帧；
- 必要块恢复后继续正常点到面更新；
- 地图缺口持续超过 `map_gap_timeout_sec` 后进入 `LOST`，防止长时间纯 IMU 漂移；
- 必需块损坏、索引越界或反序列化失败时，报告地图错误并进入 `LOST`；
- 非核心预取块失败不影响当前 Scan，但记录错误并停止使用该块。

该保护只处理短暂 I/O 延迟和线程抖动。正常情况下，`30 m` 加载范围与运动前视应使新块在车辆到达前完成加载。

## 11. 与原有组件的关系

### 11.1 保留的功能

- YAML `x/y` 先验限制 BTC 候选范围；
- BTC 半径逐级扩大和全局回退；
- BTC 几何验证、normal ICP 和 GTSAM Session 对齐；
- RViz `/initialpose` 的 `x/y/yaw`；
- IMU 提供 RViz 初始化的 `roll/pitch`；
- 历史关键帧二维 KD-Tree 提供最近高度 `z`；
- 定位质量监控与 `LOST` 恢复；
- 历史地图只读约束。

### 11.2 被替换的功能

连续定位不再使用：

- 历史关键帧三维 KD-Tree 选择活动关键帧；
- `local_map_max_load_per_scan`；
- 将活动关键帧转换为一个合并世界点云；
- 活动集合改变后调用 `cut_voxel()` 完整重建固定 `surf_map`。

历史关键帧数据及二维 KD-Tree 仍然保留，因为 BTC 先验选择和 RViz 最近高度查询需要它们。

## 12. 版本兼容与转换工具

地图加载行为：

- 定位程序接受完整且参数兼容的 v2 地图；
- 定位程序拒绝 v1 地图，并输出离线转换命令；
- 离线转换器显式读取 v1，再生成新的 v2 输出目录；
- 输入和输出目录不能相同，转换失败不能破坏原地图；
- 转换器完成后执行一次全索引、全块校验；
- v2 地图的关键帧与 BTC 内容保持与 v1 等价。

建议命令形式：

```bash
rosrun voxel_slam build_spatial_map \
  --input /path/to/v1_map \
  --output /path/to/v2_map
```

## 13. 测试与验证

### 13.1 单元测试

- 正坐标、负坐标和精确边界的块/体素索引；
- 块尺寸不是顶层体素整数倍时拒绝配置；
- 跨关键帧融合去重和确定性输出；
- 静态八叉树构建与原版匹配结果等价；
- 索引和块二进制往返；
- 截断文件、错误校验码、非法计数和非法节点下标；
- 加载球、卸载球、AABB 相交和滞回；
- Scan 快照在后台发布和卸载期间保持生命周期；
- 旧 Session 代数加载结果被丢弃；
- 地图未就绪时不累计坏帧，超时后进入 `LOST`；
- v1 转换后关键帧和 BTC 数据保持一致。

### 13.2 集成测试

- 建图导出 v2 后重新加载；
- BTC 重定位后预加载并进入连续定位；
- RViz 初始化在地图就绪后完成连续 Scan 验证；
- 跨越块边界时匹配连续，无完整体素地图重建；
- 回到已经访问过的块时能够重新加载；
- 模拟慢磁盘、块损坏和预加载超时；
- `LOST` 后重新 BTC，并确认旧异步结果不会污染新 Session。

### 13.3 Ubuntu 实测指标

Windows 环境只能进行不依赖 ROS 运行时的检查。最终必须在 Ubuntu 20.04、ROS Noetic 和目标数据集上记录：

- 索引加载时间；
- 单块读取、校验和反序列化时间；
- 活动块、根体素、节点和平面数量；
- IESKF 点到面匹配时间；
- 每 Scan 总时间的平均值、P95 和最大值；
- 块切换前后的耗时曲线；
- 内存峰值和后台 I/O 带宽；
- 轨迹误差、重定位成功率和 `LOST` 次数。

实时性验收以目标激光帧周期为准。除了初始 `PREPARING_LOCAL_MAP`，块加载和卸载不能在里程计线程中产生超过帧周期的同步停顿。

## 14. 实施边界

实现应拆分为独立组件，避免继续扩大 `voxelslam.cpp`：

- 空间索引与静态数据结构；
- 空间块构建器；
- v2 索引和二进制块 I/O；
- 后台块管理器与活动快照；
- 静态点到面匹配器；
- v1 到 v2 转换工具；
- ROS 参数、状态发布与主流程接线。

实施顺序应先完成纯数据结构、索引、序列化和单元测试，再接入地图导出，最后替换定位连续跟踪路径。原有关键帧局部地图实现保留到新路径完成等价性与性能验证后再删除。

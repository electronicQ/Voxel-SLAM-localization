# README 项目化重构设计

## 目标

将根目录 `README.md` 从“原版 Voxel-SLAM 中文说明 + 后追加定位章节”重构为当前二次开发工程的主文档。读者打开 README 后，应首先理解本项目基于 Voxel-SLAM 做了哪些改造，随后可以按顺序完成建图、地图导出、重定位、连续定位和导航接入，并在后半部分复习各模块的技术原理。

## 文档定位

- 当前工程是基于 Voxel-SLAM 的二次开发项目，不以原版论文、竞赛成绩或数据集演示作为开篇主体。
- README 同时服务于三类读者：首次运行项目的使用者、检查工程能力的代码阅读者，以及需要复习项目流程的作者本人。
- 原版 Voxel-SLAM 的仓库、论文、视频和竞赛信息保留在文末“上游项目与致谢”中，明确来源但不喧宾夺主。
- 不修改程序行为、配置格式和运行接口；本次只重构文档。

## 章节结构

### 1. 项目简介

用简短段落明确说明：本项目基于 Voxel-SLAM，保留其 LiDAR-IMU 前端、点到面 IESKF、局部 BA、BTC 和 GTSAM 能力，并围绕可复用地图定位完成二次开发。突出三类改造：

1. 建图完成后生成只读 v2 空间体素块地图包；
2. 新增 BTC 自动重定位和 RViz 人工初始化双通道；
3. 使用增量空间块加载实现连续 in-map tracking，并提供导航所需的 IMU 高频里程计。

### 2. 功能概览

用紧凑列表给出当前版本真正具备的能力，包括建图、地图导出/转换、重定位、连续定位、失效恢复、定位状态接口和 SCAN-Planner 适配。避免把原版数据集示例混入功能概览。

### 3. 环境与编译

保留 Ubuntu 20.04、ROS Noetic、PCL、Eigen、GTSAM、Livox 驱动等依赖。克隆命令不再固定指向原版上游仓库，而是用当前仓库放入 catkin 工作空间的通用写法。明确 Windows 只能进行静态检查和部分 Python 测试，完整构建与 rosbag 验证必须在 Ubuntu 进行。

### 4. 完整运行流程

该部分放在原理介绍之前，并严格按实际使用顺序组织：

1. 配置建图参数；
2. 运行建图并通过 `finish` 触发最终优化和 v2 地图导出；
3. 必要时使用 `build_spatial_map` 转换 v1 地图；
4. 配置并启动定位；
5. 等待 BTC 自动重定位，或通过 RViz `2D Pose Estimate` 提供人工初始位姿；
6. 使用 `/localization/state` 和 `/localization/valid` 判断是否进入有效定位；
7. 可选启动车辆里程计适配器并接入 SCAN-Planner。

每一步保留可复制的命令、关键 YAML 参数和成功判据。运行流程只解释“怎么做”，不在这里展开完整算法推导。

### 5. 建图与定位原理

按数据流组织，而不是沿用原 README 的 `4.5.x` 附加章节结构：

- 建图与地图准备：原版建图前端、最终优化、世界系点云融合和固定空间块生成；
- v2 地图包：manifest、关键帧、BTC 数据库、空间块索引与二进制数据的职责；
- BTC 自动重定位：局部里程计 Session、查询关键帧生成、候选检索、平面 ICP、GTSAM 当前 Session 对齐及 `T_W_O` 计算；
- RViz 人工初始化：x/y/yaw 来源、IMU roll/pitch、最近历史关键帧 z，以及连续局部地图匹配验证；
- 连续定位：邻域网格枚举、哈希索引查块、后台增量加载、不可变快照、点到面 IESKF 和卸载滞回；
- 失效与恢复：坏帧、地图缺口、状态异常触发 `LOST` 后返回局部里程计；
- 高频里程计：权威激光后验与独立 IMU 频率前向传播的关系、输出门控和导航适配。

保留现有坐标系定义、关键公式和流程图式文本，删除重复解释。

## 最终审查后的接口修正

最终整体审查发现，文档中的两个运行接口必须先与实际程序行为统一：

1. 仓库提供的 RViz 配置使用 `camera_init` 作为 Fixed Frame，而初始位姿缓冲区原先只接受 `map`/`/map`。由于本工程将 `camera_init` 作为历史地图世界坐标系和定位输出父坐标系，程序应同时接受 `camera_init`、`/camera_init`、`map` 和 `/map`；README 应以默认 `camera_init` 流程为主，并将 `map` 说明为兼容别名。
2. SCAN-Planner 的 `cloud_is_world` 只决定输入点云是否需要再变换；`need_extrinsic` 独立决定输入的 IMU 位姿是否需要转换到 LiDAR 射线原点。当前接入使用 `/LIO/odom_imu` 作为传感器位姿且 Mid-360 外参非零，因此应设置 `cloud_is_world=true`、`need_extrinsic=true`，并确保 SCAN-Planner 的 LiDAR 外参与 `General/extrinsic_tran`/`extrinsic_rota` 一致。

README 还必须说明：SCAN-Planner 是外部工程，应放入同一 catkin 工作空间或正确 source overlay；其上游 `run.launch` 会设置 Go2 `robot_description` 并启动 `robot_state_publisher`，使用用户自有 URDF 时必须复制并裁剪该 launch，避免重复覆盖机器人描述和 TF。环境依赖补充 Boost filesystem/system，并建议使用 `rosdep install`。这些修正不改变既有 BTC、RViz 验证、连续定位或高频里程计算法流程。
